# DaveHarness 0.6.0 cancellation and deadline contract

H4 adds `CancellationToken`, `ExecutionContext`, `OperationController`, and an injected `CancellableToolRunner`. The context carries run and call IDs, absolute monotonic run/model/tool deadlines, an output budget, a cancellation signal, and an optional event callback for H5. The durable `RunSnapshot.deadline_at` is derived once from creation time and the total wall budget. A controller pins that deadline to one monotonic instant for the active run, so wall-clock rollback cannot extend it. On process-boundary reattachment, the remaining UTC duration is translated into the new process's monotonic clock; it is never reset to a fresh full budget.

`resume_run` and `decide_run` accept an injected monotonic clock, controller, and runner. A model or tool operation is bounded by the earlier of its own timeout and the total run deadline. Fake-clock tests cover exact deadline boundaries and a run that reaches its total limit across individually successful steps. The legacy budget may omit the new total deadline. Existing DaveLLM routes retain their shipped step and error limits.

`cancel_run` accepts `running` state, first moves it to `cancelling` through compare-and-swap, and requests stop from the per-run controller. It emits `cancelled` only after active work acknowledges termination. Refusal, missing ownership of an active operation, or stop timeout yields `cancellation_failed`; a late result cannot replace the terminal snapshot. Cancellation against `created` or another nonrunning state is nonexecuting. The H4 suite proves a single winning terminal transition under repeated completion/cancel races; H5 adds versioned terminal events and retention.

A tool must explicitly opt in with `context_handler=True` and an injected runner. The built-in `CooperativeToolRunner` passes the context to the registered handler and acknowledges stop only after the handler task finishes. Hosts may inject process-backed runners that use the same acknowledgment contract. An acknowledged tool timeout keeps `status=timeout` and records `termination=cancelled`; an unacknowledged stop ends the run as `cancellation_failed` before another call. Each tool call has a fresh cancellation token. A tool declared `bounded` is not automatically hard cancellable. Legacy synchronous handlers still run through `asyncio.to_thread`; their timeout remains `status=timeout` with `termination=deadline_abandoned`, meaning the thread may continue. The new runner does not change existing status strings or DaveLLM endpoint fields. DaveLLM still owns tool enablement, shell opt-in, authentication, roots, transport, and persistence.
